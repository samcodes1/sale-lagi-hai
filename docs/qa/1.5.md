### Security (deep links, secure-dev checklist)
- **Android deep linking is off.** `flutter_deeplinking_enabled=false` (`AndroidManifest.xml:46-48`). There's no `VIEW` intent filter and no `autoVerify`. QA's manifest test guards both.
- **Untrusted parameters are validated before any lookup.** `RouteParams.isId` accepts lower-case UUIDs only; `isSlug` accepts `[a-z0-9]+(-[a-z0-9]+)*`, at most 64 characters. Dart's `$` doesn't match before a trailing newline (tested).
- **Hostile inputs never reach a detail page, and nothing throws.** Tested: `/deal/` (empty), `%0A` and `%20` padding, a UUID without hyphens or with a trailing `-`, `javascript:alert(1)`, `%2e%2e%2f`, a 65-character slug, `a--b`, `-khaadi`, `%00`, a 5,000-character slug, and `food_and_dining`.
- **A query string can't override the path parameter.** `?dealId=evil` still opens the path's deal.
- **The Not found screen never echoes the location.** Tested with `/deal/<uuid>/%3Cscript%3Eabc`.
- **Developer routes redirect to `/profile` in prod.** Both `/profile/dev/theme` and `/profile/dev/gallery` (the gallery case was untested before) redirect, and their links are hidden.
- **No `print(`, no `http://` and no secrets** in the router or shell code.
- Out of scope: `allowBackup="true"` and the network config are the in-progress 1.7 commit (`b7d1c19`). Not reviewed here.

### S4-1: iOS deep linking isn't switched off
`ios/Runner/Info.plist` has no `FlutterDeepLinkingEnabled` key. Since Flutter 3.27 the default is **on**. Today no URL types or associated domains exist, so no link can arrive. But the Android comment's promise ("links will arrive through one validating DeepLinkService") isn't enforced on iOS. **Fix:** add `<key>FlutterDeepLinkingEnabled</key><false/>`.

### S4-2: Developer pages ship in prod
`routes.dart:191-225` (plus the `TypedGoRoute`s at `:57-58`) registers the theme preview and gallery in every flavor, and `_devOnly` redirects at runtime. The widget code, including its sample data, is compiled into the prod build. It's not a hole (the redirect is tested), but it is dead weight and attack surface. **Fix:** register the dev routes only when a compile-time `FLAVOR != 'prod'` holds, so tree-shaking removes them.

### S4-3: No back from a cold-opened Not found page
`app_router.dart:14` uses `errorBuilder` as the only page. Opened from an external link, system back exits the app (`handlePopRoute` returns false). The "Go to Home" button works. **Fix (optional):** make back on Not found go Home.

### S4-4: `go()` to a deal returns to Home, not the tab you were on
`DealRoute` is a child of `/` (`routes.dart:33-40`), so `go('/deal/…')` from Explore switches the shell to Home under the deal. `push` keeps the current tab (QA test passes for Saved). That's fine for notifications. In-app taps (Phase 4) must use `push`, or the doc comment at `routes.dart:22-24` doesn't hold.
