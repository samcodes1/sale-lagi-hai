### BUG-1 (S3): Under a minute left, expiry reads "Ends in 0 hours"
- **Area / file:** `lib/core/l10n/deal_time_labels.dart:28`
- **Environment:** any locale; unit test.
- **Steps:** `DealTimeLabels(en, …).expiry(now + 30 s, now: now)`.
- **Expected:** "Ends in 1 hour" ("1 گھنٹے میں ختم"). The comment on line 27 promises "never 0 hours".
- **Actual:** `Ends in 0 hours`. `remaining.inMinutes` truncates 30 s to 0, and `ceil(0 / 60)` is 0. This happens for the last 59 s of every deal, which is when an "ending now" label is most visible.
- **Evidence:** `test/qa/l10n_qa_test.dart` "under a minute left never reads 'Ends in 0 hours'" fails in known-bug mode: `Actual: 'Ends in 0 hours'`.
- **Suggested fix:** `final hours = (remaining.inSeconds / 3600).ceil();`, or clamp it to at least 1.
- **Regression test:** the QA test above (drop its `knownBug` skip).

### BUG-2 (S3): The "Urdu numerals" option skips the discount badge and every relative time
- **Area / file:** `lib/core/l10n/formatters.dart:38` (`discount` doesn't call `_digits`). `lib/core/l10n/deal_time_labels.dart:29,33,42-61`: every plural message gets a raw `int`, and gen-l10n prints it with Western digits. The Urdu ARB also hard-codes "1" in its `=1` branches (`app_ur.arb:31-40`).
- **Steps:** `AppFormatters(ur, ur, urduDigits: true)`. Then call `.discount(40)`, and `DealTimeLabels(ur, that).expiry(now + 2 h)` / `.verified(now − 5 min)`.
- **Expected:** ۰–۹ everywhere, as the plan's "Urdu numerals as an option" and rtl-urdu.md §6 ask. Map number spans after formatting.
- **Actual:** `⁦-40%⁩`, `2 گھنٹوں میں ختم`, `5 منٹ پہلے تصدیق ہوئی`. Only `number`, `price` and `shortDate` map, so one card would mix "۲,۹۹۹ روپے" with "-40%" and "3 دن".
- **Evidence:** `test/qa/l10n_qa_test.dart` "the discount badge and relative times use Urdu digits too" fails: `Actual: '⁦-40%⁩'`.
- **Severity rationale:** S3. The option isn't exposed in any setting yet (nothing creates `AppFormatters(urduDigits: true)`), so no user sees this today. It must be fixed before a setting is added.
- **Suggested fix:** Pass `urduDigits` into `DealTimeLabels` and apply `toUrduDigits` to the results of `discount`, `upTo/flatPercentOff` and the plural messages. Or give those placeholders a `String` type and pass pre-formatted numbers. Replace the literal "1" in the Urdu `=1` branches with `{count}`.

### BUG-3 (S3): Urdu "Flat N% off" renders the percent sign before the number ("%30")
- **Area / file:** `lib/l10n/app_ur.arb:51` `"flatPercentOff": "فلیٹ {percent}% رعایت"`. It is shown by `DiscountBadge` (`deal_labels.dart:20`) and by the theme preview's Localization sample.
- **Environment:** web release build, `ur-PK`, light and dark, 360 and 412.
- **Steps:** Open `/#/profile/dev/gallery` (or `/profile/dev/theme`) in Urdu and look at the "Flat 30%" badge.
- **Expected:** "30%" keeps its order, as in "70% تک رعایت" next to it. rtl-urdu.md §5 names this exact failure ("50%" rendering as "%50") and says to isolate inserted values.
- **Actual:** "%30". The number follows an Arabic letter, so bidi rule W2 makes the digits Arabic numbers (AN). The `%` is then a neutral and resolves to RTL, which puts it on the left. "Up to" is fine only because its number starts the string.
- **Evidence:** `docs/qa/screens/1.6/gallery_360x800_light_ur-PK_p4.png` (badge row) and `docs/qa/screens/1.4/theme_412x915_dark_ur-PK_p5.png` ("فلیٹ %30 رعایت"). Test: `test/qa/l10n_qa_test.dart` "Flat N% off: '30%' reads 3-0-% left to right in Urdu" fails (`%` at x=120 is left of `0` at x=160).
- **Severity rationale:** cosmetic (S4) on its own, escalated one level because every Urdu user sees it on every flat-discount badge.
- **Suggested fix:** `"فلیٹ ⁦{percent}%⁩ رعایت"`, as `discountBadge` already does. Use the same pattern in `upToPercentOff` for consistency.

### S4-1: Doc inconsistency on expiry thresholds and time zone
The implementation (`deal_time_labels.dart:4-11`) shows hours under 6 h, then calendar days up to 3, then the date. That matches flutter-ui-ux SKILL.md:185-186 (">72h → date"; the deliberate decision). `references/deal-patterns.md:46-49` says ">7 days → date", "1h–24h: 5h 12m" and "<1h: mm:ss", and "Plain date in **Asia/Karachi**". The code uses the device's time zone, so a Pakistani abroad sees the end date shifted. **Fix:** update deal-patterns.md to the chosen policy, and decide whether expiry uses PKT (rtl-urdu.md §6 says "Always compute in Asia/Karachi").

### S4-2: Theme preview's Latin samples are scrambled in RTL
`lib/design_system/gallery/theme_preview_page.dart:192` hard-codes `'-40%'`, which renders "40%-" in Urdu. Line 237's subtitle "25% off dinner · Do Darya · ends tonight" renders as "off dinner · Do Darya · ends 25% / tonight" (`1.4/theme_412x915_dark_ur-PK_p5.png`). It's a dev-only page, but it's the page visual QA uses. **Fix:** use `format.discount` and `ContentText`.

### S4-3: `emptySearch` doesn't isolate the user's query
`app_ur.arb:61` `“{query}” کے لیے…`. The query is user content in either script (users type Roman Urdu), and the skill (SKILL.md:122) says to wrap it in FSI/PDI. There's no screen yet, so nothing shows it. **Fix:** `“⁨{query}⁩”`.

### S4-4: "yesterday" for anything 24–47 h old
`deal_time_labels.dart:49-51,59-61` use `inDays == 1` → "Verified yesterday" / "کل تصدیق ہوئی". At 09:00, something verified 46 h ago (11:00 two days back) reads "yesterday". **Fix:** "1 day ago", or compare calendar days as `expiry` does.

### S4-5: The phone language isn't followed live
`locale_controller.dart:25-27` reads `PlatformDispatcher.instance.locale` once. A user who never picked a language and changes the phone language while the app runs keeps the old language until restart. Only the first preferred locale is considered (`[en_US, ur_PK]` gives English). **Fix (later):** listen to `onLocaleChanged`, and resolve against the whole `locales` list.

### S4-6: Stale comment in `l10n.yaml`
`l10n.yaml:2` says "(gitignored)", but 1.5 committed `lib/l10n/gen/` and CI checks that it's fresh.
