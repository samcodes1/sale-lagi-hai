Suggested fixes:
- **J1:**
  - Revoke the table-wide insert and grant only the client columns: `grant insert (deal_id, reason, note) on reports`; `grant insert (kind, brand_name, brand_id, title, details, url, city_id, image_path, ends_at) on submissions`.
  - Or force `new.created_at := now()` in the rate-limit triggers for non-trusted callers.
  - Do the same for the other tables where `created_at` is client-insertable (deals, placements, follows and so on), for consistency.
- **J2:** Leave the queue row unprocessed when the deal isn't live yet but may become live (future `starts_at`, or an inactive brand), so a later run picks it up. Drop it when it's removed, rejected or ended. Alternatively, `queue_alerts` on `starts_at` passing (from `expire_deals`) and on brand activation.
- **J3:** Add `when (old.status is distinct from new.status)` to the trigger (as the audit triggers do), and keep "alerted once" in a durable column (`deals.alerted_at`) rather than in a row cleanup deletes.
- **J4:** Cap tokens per user in `register_push_token` (delete the oldest beyond 10), and rate-limit registrations.
- **F1:** Treat as dead only `UNREGISTERED`, or `INVALID_ARGUMENT` whose message or fieldViolation refers to `message.token`. Treat any other 404 or 400 as `failed`, and alert on it.
- **F3:** Map 401 to `retry` and clear `this.token`. Consider 403 `PERMISSION_DENIED` a configuration failure (`retry` plus an alarm), not a closed push.
- **F4:** Cache the in-flight token promise.
- **F5:** Map `SENDER_ID_MISMATCH` to `dead-token`.

## Recommendations (non-blocking)
- Brand followers get alerts for local deals in any city. Consider filtering local deals by the follower's `profiles.home_city_id` or followed cities.
- The planner counts users' cards even when the card product or bank is inactive (`jobs.sql:286-292`). Filter on `is_active` to match `deals_for_my_cards`.
- `register_push_token` lets anyone holding a token take it over (the documented "phone switches accounts" case). That's acceptable because tokens are secret, but note it in JOBS.md.
- Delivery is at-least-once: a crash between sending and `mark_pushes_sent` resends after 10 min. `collapse_key` and `tag` per deal make the duplicate replace the first on Android. Document this.
- Run `deno check` locally before the phase gate. QA could not.

## Fixes after round 1 (for re-test)
- **2.5-J1 (S2), fixed.** The rate-limit triggers set `created_at := now()` for every untrusted caller, so backdated rows count.
- **2.5-J2 (S2), fixed.** The planner picks up only rows it can finish now: live deals, and deals that are no longer published or have ended. A published deal that isn't live yet (it starts later, or its brand is inactive) stays queued and alerts once it goes live.
- **2.5-J3, fixed.** `alert_queue.alerted_at` records that a deal alerted, and cleanup keeps those rows, so a deal alerts once, ever. A deal dropped before it alerted is queued again if it's republished.
- **2.5-J4, fixed.** `register_push_token` keeps a user's 10 most recently seen tokens.
- **2.5-F1 and F2, fixed.** A token is dropped only for `UNREGISTERED`, `SENDER_ID_MISMATCH` (F5, S4), or `INVALID_ARGUMENT` about the registration token (field `message.token`, or a message naming the registration token). A plain 404 or a bad payload field is `failed`. My `fcm.test.ts` assertion that encoded the old rule was corrected.
- **2.5-F3, fixed.** On a 401, the client forgets the cached OAuth token and retries once. A second 401 is `retry`.
- **2.5-F4 (S4), fixed.** Concurrent first sends share one OAuth exchange.
- J5 (S4): deferred.
