### 4.7-A1 (S3): a stored card the catalog no longer lists is invisible and can't be removed
- **Area / file:** `lib/features/cards/presentation/my_cards_screen.dart:78-92`. Rows are drawn only for ids found in `cardProductsProvider`.
- **Steps:** have a card on the phone whose product is no longer listed: the bank retired it (`card_products.is_active = false`, which RLS then hides), or it is a demo id from before this build changed them. Open My Cards.
- **Expected:** a row to remove it ("A card no longer offered"), or the app drops it.
- **Actual:**
  - "Your cards" shows with nothing under it, and the empty state with Add a card never returns;
  - the card can't be removed but still counts toward the 20;
  - it is still sent to `deals_for_cards`, where it matches nothing.

  Workaround: clear the app's data.
- **Evidence:** `test/qa/my_cards_qa_test.dart` "QA BUG 4.7-A1" (fails).
- **Fix:** once products have loaded, show unknown ids as a removable "Card no longer offered" row, or drop them from `myCardsProvider` (and from `user_cards`).

### 4.7-A6 (S3): guest cards don't reach the account at sign-in unless My Cards was opened this session
- **Area / file:** `lib/features/auth/application/auth_providers.dart:76-77`. `ref.read(myCardsProvider)` on a provider not yet built returns its starting `[]`, because the stored copy is still loading.
- **Steps:** as a guest, add a card. Restart the app, then sign in without opening My Cards.
- **Expected:** the card is copied into `user_cards`, as MY_CARDS.md says ("Cards added as a guest move into the account at sign-in").
- **Actual:** nothing is copied. The planner builds card alerts from `user_cards` (`jobs.sql:315-321`), so this shopper never gets them. Workaround: remove the card and add it again while signed in.
- **Evidence:** "QA BUG 4.7-A6" (fails: no `user_cards` insert).
- **Same pattern:** saved deals, `auth_providers.dart:59` (4.4).
- **Fix:** give `StoredStringList` a `Future<List<String>> loaded` that the sync awaits, or have the sync read the stored copy itself.

### 4.7-P1 (S3): a report note accepts a full card number
- **Area / file:** `public.reports.note` (`20261029120500_moderation_and_commerce.sql:18`). The app's report sheet note (`deal_detail_screen.dart:582`, 500 characters) has no check.
- **Steps:** on a card offer, Report → Other → "Didn't work with my card 4111 1111 1111 1111 exp 12/29" → Send.
- **Expected:** "We never ask for card numbers" holds: PAN-like digits are refused, or masked before storing.
- **Actual:** it is stored, and moderators read it. My Cards itself is clean (below). This is the one path found where a card number enters the database, and card offers invite exactly that note.
- **Evidence:** `qa_my_cards.test.sql` "QA BUG 4.7-P1" (fails: the insert succeeds).
- **Fix:**
  - a check on `reports.note` (and later `submissions.details`) refusing 13–19-digit runs, with separators, that pass Luhn;
  - in the app, an inline "Don't include card numbers" hint and the same check before sending.

  `LogRedactor` already has the Luhn rule to reuse.

### 4.7-A3 (S4): system Back on the card types closes the sheet instead of returning to the banks
The in-sheet back icon returns to the banks, but there is no `PopScope` (`my_cards_screen.dart:247-424`), so system Back closes the whole sheet. MY_CARDS.md says "Back returns to the banks". Reproducer: "QA BUG 4.7-A3" (skipped; fails unskipped).

### 4.7-A4 (S4): adding while the stored list loads ignores the 20 stored cards
`my_cards_providers.dart:41-60`: `added` is decided against the in-memory list, which is empty while loading. With 20 stored cards, the 21st is reported added (toast) and mirrored to `user_cards`, then dropped when replayed onto the stored 20. Reproducer: "QA BUG 4.7-A4" (skipped). Fix: decide after the replay (await the load first).

### 4.7-A5 (S4): changes made while storage couldn't be read are lost when it reads again
`lib/core/storage/stored_string_list.dart:108-114`. Once the first read has failed, a change that finds storage readable again applies only itself to the stored copy, so changes made in between disappear from memory and storage. Two changes racing while unreadable also lose the first. It needs storage read errors, hence S4, but it affects saved deals, recent searches and cards alike. Reproducer: "QA BUG 4.7-A5" (skipped). Fix: keep unwritten changes in a queue (like `_pending`) and replay them all onto the stored copy once a read works.

### 4.7-A7 (S4): at 200% text the Explore "My cards" chip is cut, and in Urdu the start of the label is lost
The Explore entry is a one-line chip, so at 200% text the label is clipped. In English the end fades ("My cards: see your card…"). In Urdu the **start** is gone ("…کارڈز کی رعایتیں دیکھیں"), so "میرے کارڈز" (My cards) itself isn't visible. Evidence: `docs/qa/screens/4.7/explore-chip_360x800_light_en-ur_ts2.png`. Fix: a full-width tile or button that wraps, like Profile's "My cards" row, or a shorter label.

### 4.7-C1 (S4): a two-dimensional `card_product_ids` array passes the 20-card cap
`20261029230000_my_cards.sql:24`: `[1:20]` slices only the first dimension, so `{{20 ids},{19 ids, real}}` reads all 40. The card catalogue is small, so this is mostly about the cap's meaning, not load. Reproducer: `qa_my_cards` "QA BUG 4.7-C1" (todo). Fix: `(select array_agg(x) from unnest(ids) with ordinality u(x, n) where n <= 20)`, or refuse `array_ndims(ids) > 1`.

### 4.7-C2 (S4): the alert planner still matches retired card products
`private.plan_alerts` (`20261029160000_jobs.sql:315-321`) has its own copy of the card rule, without `cp.is_active` and without the 20-card cap. A retired card brings alerts for offers My Cards no longer lists. MY_CARDS.md says `deals_for_my_cards` is the rule "for the alert planner", but the planner doesn't call it. Reproducer: "QA BUG 4.7-C2" (todo), plus a passing control showing the planner ran. Fix: add `and cp.is_active` there, or share one SQL helper.

### 4.7-C3 (S4): `cardProducts()` reads without a limit and would silently stop at PostgREST's 100 rows
`backend_catalog_repository.dart` `cardProducts()` has no limit or paging, and PostgREST's `max_rows` is 100 (`config.toml:13`). Today 36 products are seeded, but a real catalogue (Classic, Gold, Platinum, Mastercard and UnionPay tiers across about 30 banks) passes 100. Products past the 100th by name would vanish from the sheet, and their stored cards would hit A1. Fix: load products per bank when a bank is picked, or page. Relatedly, an unknown `network` value throws a `FormatException` that fails the whole list; dropping the one row would be more robust.

## Backend review
- **Matching** (`qa_my_cards`):
  - Visa Credit gets the Visa offer only: not the debit-only one, not the Mastercard product's.
  - Visa Debit gets the Visa and debit offers.
  - Mastercard Credit gets its own product's offer and not the Visa one.
  - Draft offers and hidden brands' offers never appear.
  - A retired product matches nothing.
  - Nulls in the list are ignored, and the same card 25 times counts once.
  - 5,000 ids are not an error, and `page_size` is clamped.
- **What a guest's ids reach:** only live card offers of active brands, through `deal_cards`. Anon can't read a retired product.
- **`user_cards` RLS:**
  - anon can't add or read;
  - a shopper adds their own, with `user_id` defaulting to them;
  - a shopper can't add for, read or remove someone else's cards;
  - there is no update;
  - a duplicate is 23505, which the app logs as "already synced";
  - staff, even a moderator with MFA, read no shopper's cards.
- **`deals_for_my_cards`** is the same rule over the caller's own cards; the developer's test checks equality. It keeps its 2.3 grant (no anon), re-checked in `qa_phase2_roles`. It still has no pinned `search_path`; it is invoker and fully qualified, so this is acceptable.
- **Process note:** 4.7 again edited an already-written migration, `20261029120400_user_activity.sql` (`default auth.uid()` on `follows`, `saves` and `user_cards`). That is harmless before the first deploy; after it, changes need a new migration file.

## `StoredStringList` review (used by saved deals, recent searches and My Cards)
- Sound:
  - changes during the first read are replayed onto the stored copy (QA test with a held read, on the phone too);
  - an unreadable store is never overwritten;
  - a corrupt copy reads as empty;
  - logs carry only the error type;
  - the generation guard drops reads from before a rebuild;
  - `take(limit)` everywhere.
- Weak points:
  - A5: changes made between a failed read and the next good one are lost.
  - A4: callers that decide from `state` during the load can be wrong.
  - There is no way to await the load, which is the root of A6.

  A `Future<void> get ready` would fix A4 and A6.

## Recommendations (non-blocking)
1. **Cards on a new phone.** Signing in on a second phone doesn't bring the account's cards (or saves) to it, because "the deals come from the phone's list for everyone". Profile promises "Sign in to keep your saves on any phone". Consider merging `user_cards` into the phone's list at sign-in.
2. **Card names.** "HBL Visa Credit (Credit)" says credit twice. Show the kind only when the product name lacks it.
3. **Sheet row semantics.** Add `Semantics(button: true)` to the sheet's bank and card rows, as 4.6-A3's fix did for search rows.
4. **Duplicate inserts.** The mirror re-inserts a card that's already there, which logs a 23505. An upsert (`on conflict do nothing`, via `Prefer: resolution=ignore-duplicates`) would keep the logs clean.
