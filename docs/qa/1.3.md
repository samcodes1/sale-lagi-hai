### R2-1 (S3): IconButton toggle variants after the BUG-7 fix
- **File:** `lib/design_system/theme/app_theme.dart:148-158`. The theme sets the selected foreground to `scheme.secondary` for every variant and leaves the other states to Material's defaults.
- **Steps:** `flutter test test/qa/theme_round2_qa_test.dart --dart-define=QA_KNOWN_BUGS=true --plain-name "all variants"`.
- **Actual:**

  | Variant | Theme | Icon on fill | Ratio |
  |---|---|---|---|
  | `IconButton.filled(isSelected: false)` | light | Haldi on `#E3DFD9` (M3 default: `primary` on `surfaceContainerHighest`) | 1.20 |
  | `IconButton.filled(isSelected: false)` | HC light | Haldi on `#E3DFD9` | 1.20 |
  | `IconButton.filled(isSelected: true)` | dark | `#9EA2FF` on Haldi | 1.45 |
  | `IconButton.filled(isSelected: true)` | HC dark | `#BCBEFF` on Haldi | 1.10 |
  | `IconButton.outlined(isSelected: true)` | light | Neel on ink `inverseSurface` | 2.43 |
  | `IconButton.outlined(isSelected: true)` | dark | `#9EA2FF` on `#FAF8F4` | 2.18 |
  | `IconButton.outlined(isSelected: true)` | HC | Neel/`#BCBEFF` on the inverse surface | 1.52 / 1.66 |

  The standard and tonal variants pass in all states and themes. Non-toggle filled passes. The standard variant's selected and idle states are now visually different.
- **Expected:** ≥ 3:1 (WCAG 1.4.11).
- **Severity:** S3. The common toggle, the save heart, is the standard variant, which passes. The first row is a regression: round 1's blanket `onSurface` made it pass.
- **Suggested fix:** theme per variant. The `IconButtonThemeData` style can't tell variants apart, so add a design-system `AppIconButton.filled`/`outlined` (1.6) that resolves selected → `onPrimary` on a Haldi fill, unselected → `onSurfaceVariant` on `surfaceContainerHighest`, and outlined selected → `onInverseSurface`. Or forbid the filled and outlined toggle variants with a guard test until then.

### R2-2 (S3): New state resolvers drop the disabled state
- **Files:**
  - `app_theme.dart:507-510`: `_selected()` maps every non-selected state, including disabled, to the idle colour. It's used by `dayForegroundColor`, `todayForegroundColor` and `yearForegroundColor` at `:357-363`.
  - `app_theme.dart:114-118`: the `segmentedButtonTheme` foreground ignores `WidgetState.disabled`.
- **Actual:**
  - `showDatePicker(firstDate: Oct 10, lastDate: Oct 20)`: day 5, which is disabled, has exactly the same colour as day 12 (`#1A1433`), and out-of-range "today" is full Neel.
  - A `ButtonSegment(enabled: false)` is full `onSurface` (`#1A1433`, alpha 1.0).
  - Material's defaults dim both to 38%.
- **Expected:** disabled controls look disabled (they can't be tapped, so users tap them and nothing happens).
- **Fix:** handle `WidgetState.disabled` first in `_selected` and in the segmented resolver (`onSurface.withValues(alpha: 0.38)`).

### R2-3 (S3): Dark remap regression on `surfaceContainerHigh`
- **File:** `app_theme.dart:439` (`surfaceContainerHigh: BrandColors.surma700`; it was Surma 800 in round 1).
- **Actual:** in dark, the `SearchBar` (M3 background is `surfaceContainerHigh`) hint "Search deals" is `#A29DA6` on `#433D50`, **3.91:1**. Full table for that surface: `onSurfaceVariant` 3.91, `secondary` 4.48, `outline` 2.34. The same applies to `surfaceContainerHighest` (filled cards, switch tracks and the TimePicker fields). HC dark passes, because `onSurfaceVariant` there equals `onSurface`.
- **Expected:** ≥ 4.5:1. Search is a core Phase 4 flow.
- **Fix:** keep `high` at Surma 800 and use a step between 800 and 700 for `highest` (a new Surma 750 token from the generator). Or lighten dark `onSurfaceVariant` to Surma 300 (`#CBC6C0`), which is ≈ 6:1 on 700. Add both pairs to the contrast report.

### R2-4 (S3): Primary-pullers that round 1 didn't cover
- **DateRangePicker:** `showDateRangePicker` paints today's date "29" in Haldi on `#FAF8F4`, **1.50:1**. The full-screen range calendar doesn't use the `datePickerTheme` "today" colours the way `CalendarDatePicker` does.
- **Stepper:** in light (and HC light), the active step numbers are **white on Haldi, 1.60:1**, and the inactive "3" is white on grey `#A5A1AB`, 2.53:1. Stepper has no theme hook for these. Dark passes.
- **Fix:**
  - DateRangePicker: check `DatePickerThemeData.rangePicker*` and the today colours in material_ui 1.8. If there's no hook, wrap it in the design system.
  - Stepper: use `stepIconBuilder` in a design-system stepper, or don't use Stepper (onboarding steps can be custom).
- **Regression tests:** `theme_round2_qa_test.dart` "DateRangePicker: no Haldi text" and "Stepper step numbers…".

### R2-5 (S3): `SwitchListTile(selected: true)` title takes the thumb colour
- **File:** `app_theme.dart:301-306` (`switchTheme.thumbColor` selected = `onSecondary`). SwitchListTile passes the resolved thumb colour as the ListTile `selectedColor`.
- **Actual:** the title "Selected switch tile" is `#FFFFFF` on `#FAF8F4` (**1.06:1**) in light and `#15164D` on `#0F0B1F` (1.15:1) in dark: invisible. `CheckboxListTile` and `RadioListTile` with `selected: true` are fine (their fill colour is Neel).
- **Fix:** SwitchListTile passes the thumb colour straight to its ListTile, so `listTileTheme` can't override it. Build the design-system switch tile as `ListTile` + `Switch` (1.6), or forbid `selected:` on `SwitchListTile` with a guard test. The preview page's SwitchListTile doesn't set `selected`, so it isn't affected today.

### R2-6 (S3): High-contrast dark is still under 7:1 on raised surfaces
- **File:** `app_theme.dart:456-463`. Dark HC keeps `error` at `#FF8F87` and `secondary` at Neel 200, while BUG-18 made the containers lighter.
- **Actual** (exhaustive audit, `theme_round2_qa_test.dart` "high contrast: exhaustive…"):

  | Theme | Pair | Ratio |
  |---|---|---|
  | Dark HC | error on low/container (dialogs, sheets, menus) | 6.59 |
  | Dark HC | error on high/highest | 4.71 |
  | Dark HC | error on errorContainer | 6.45 |

  The tertiary pairs are Mirch, which the app doesn't use as an M3 role. That's minor, but tertiary *is* used by M3 defaults.
- **Fix:** in dark HC use error 200 (`#FFB4AB`-like) and Neel 100, and errorContainer → Error 900. Generate the HC variants in `build_tokens.py` and let the contrast report cover every on × surface pair.

### R2-8 (S3): Urdu reading text moved to Naskh; needs an owner decision
- **File:** `app_theme.dart:476-503`. `urduTextTheme` overrides the generated tokens: `titleMedium`/`titleSmall`, `bodyLarge`/`Medium`/`Small` and `labelLarge`/`Medium`/`Small` are Noto Naskh Arabic. Only display, headlines and `titleLarge` stay Nastaliq.
- **Expected:**
  - `design/BRAND_GUIDELINES.md` §4: "Decision: **Nastaliq for everything people read**; give components room to grow instead of switching to Naskh. Naskh is bundled only as an escape hatch… Only for fixed-height numeric UI that cannot grow."
  - The brand-identity skill §7: "Use Nastaliq for all reading text; allow Naskh only for tight numeric UI."
  - `flutter-ui-ux/references/rtl-urdu.md` §7: Naskh only for "chips, tabs, inputs, nav labels… Nastaliq stays for headlines **and body**. Confirm with brand-identity."
- **Actual:**
  - Body text, which is the default `Text` style (`bodyMedium`), and list titles (`titleMedium`, i.e. deal titles) are Naskh, so almost all Urdu reading text in the app will be Naskh (`round2/urdu_components_light.png`). The brand file calls that "Arabic or 'computer Urdu'".
  - The Urdu type scale is also no longer generated from the tokens. The `urduBody`/`urduLabel` tokens in BRAND_GUIDELINES §4 and `brand_tokens.dart` no longer describe the app.
  - The preview section is still labelled "Urdu (Nastaliq, RTL)".
- **Severity:** S3. Nothing is broken, and the clipping fix works. But it reverses a recorded brand decision without sign-off, and it affects every Urdu user from 1.4 on.
- **Fix, either way:**
  1. Keep Naskh for the dense roles only (labels, chips, inputs, nav, tabs: the rtl-urdu.md list). Put `body*` and `titleMedium` back to Nastaliq, and give their components room (min heights, padding).
  2. Get the owner to change BRAND_GUIDELINES §4. Add it to §9 "Open decisions" first, regenerate the Urdu tokens from the generator so `lib/` doesn't hard-code a second type scale, and rename the preview section.

  Either way, resolve it before 1.4 ships Urdu.

## Recommendations (non-blocking)
- **Goldens:**
  - Add a light-high-contrast scenario.
  - Add a scenario hosted with `goldenHost(locale: Locale('ur'))`, instead of forcing `Directionality` inside the page.
  - Split the 1300×1680 page into per-section goldens, so one change doesn't invalidate everything.
- **Product guard test:** render a catalogue of every M3 widget with `AppTheme.light()` and fail if any `RenderParagraph` or icon resolves to `scheme.primary`. That turns the brand rule into a test, instead of relying on token-pair tests.
- **Web font fallback:** set `fontFallbackBaseUrl` in `web/index.html` / `flutter_bootstrap.js` to a local path (or empty). A missing glyph would then fail loudly in QA instead of silently fetching from `fonts.gstatic.com` in production. Check FSI/PDI behaviour in 1.4.
- **Cupertino icons:** the web build warns that `CupertinoIcons` is referenced but not bundled (material_ui adaptive widgets). Either add `cupertino_icons` or confirm that no adaptive icon is used. Also remove the stale "Cupertino Icons" comment in `pubspec.yaml:40-41`.
- **Motion:** the tokens (`BrandMotion`) are in place. theming.md §5 also asks for a `motion(context, d)` reduce-motion helper and a `pageTransitionsTheme`; add both in 1.5 or 1.6.
- **Docs conflict:** theming.md says buttons are stadium, cards 16 and NavigationBar 80. BRAND_GUIDELINES says buttons 8 and cards 12. The code follows the brand file. Reconcile theming.md.
- **Small polish:**
  - Slider: the thumb is Neel, but the value bubble falls back to Haldi.
  - TextField: when a field has an error, the floating label stays grey, because the theme `labelStyle` overrides the error colour.
  - Urdu `Badge`: the label uses `urduBodySmall` (15/2.1), which makes a ~32 dp red disc.
  - `iconButtonTheme`: give the selected state its own colour.
- **High-contrast tokens:** move the HC outline values (`surma800`, `surma200`, `surma500`, `surma400` at `app_theme.dart:326-327`) into the token generator and the contrast report.
